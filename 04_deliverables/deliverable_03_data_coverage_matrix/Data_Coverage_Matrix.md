## 2. Analytics Gaps Register (15 Strategic Gaps)

| Gap ID | Domain | Gap Description | Current State in Data | Business & Analytical Impact | Severity / Priority | Recommended Remediation | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| GAP-001 | Withdrawals | Absence of Standalone Withdrawals Transaction Ledger | No withdrawal events in Feature_Events; no withdrawals sheet provided (~1,200 expected) | Cannot calculate withdrawal request volume, fulfillment rate, processing latency, or payout method distribution | Critical | Implement dedicated `withdrawals` table and instrument `withdrawal_requested`, `withdrawal_processing`, `withdrawal_completed`, `withdrawal_rejected` events | Proposed |
| GAP-002 | Wallet | Absence of Immutable Double-Entry Wallet Transaction Model | Only static `xp_balance` in Users and `wallet_viewed` in Events; no transaction ledger (~3,500 expected) | Cannot perform financial reconciliation, balance auditing, currency flow tracking, or fraud detection | Critical | Establish `wallet_transactions` ledger with immutable transaction IDs, currency units (XP/Gems/Cash), source references, and reversal links | Proposed |
| GAP-003 | Rewards | Separation of Task Activity from Reward Credit Lifecycle | Task_Activity contains `reward_status`, but no dedicated `rewards` ledger (~5,000 expected) with exact reward unit and disbursement time | Ambiguity between task completion verification and financial disbursement; inability to audit pending vs credited rewards | High | Create distinct `rewards` table with full lifecycle: Viewed -> Started -> Completed -> Validated -> Credited/Pending/Reversed | Proposed |
| GAP-004 | Referrals | Missing Relational Referrer-Referee Conversion Link | Referral events exist (created, shared, viewed) and acquisition source has text names, but no table links referring user to referee's user_id | Inability to calculate viral coefficient (K-factor), referral conversion rates, or attribute referral commission payouts | Critical | Deploy `referrals` entity linking `referring_user_id` to `referred_user_id` with registration, activation, and qualification timestamps | Proposed |
| GAP-005 | User Lifecycle | Absence of Telemetry Stream for Registration & Login Events | Registration and last login are static timestamps in Users table; no event records exist in `Feature_Events` stream | Cannot measure multi-device sign-ins, login failure rates, auth provider switches, or drop-offs during onboarding steps | High | Instrument atomic client/server events: `user_registered`, `user_logged_in`, `onboarding_started`, `onboarding_completed` | Proposed |
| GAP-006 | Tap & Earn | Missing Tap Volume & Anti-Cheat Payload in Tap Events | Events sheet records `tap_started` and `tap_completed` but contains no payload indicating tap count, duration, or taps/second | Impossible to audit bot/autoclicker behavior, tap frequency distribution, or player fatigue patterns | Medium | Add payload attributes: `tap_count`, `duration_seconds`, `taps_per_second`, `client_integrity_hash` to `tap_completed` event | Proposed |
| GAP-007 | Spin the Wheel | Missing Prize Outcome & Cost Payload in Spin Events | Spin events record start and completion, but lack properties for prize won, prize value, currency spent, and RNG audit hash | Cannot audit wheel economy, prize distribution variance against theoretical probabilities, or wheel ROI | High | Add properties: `spin_cost_gems`, `prize_type`, `prize_value`, `rng_seed_id` to `spin_completed` payload | Proposed |
| GAP-008 | Currencies | Lack of Distinction Between XP, Gems, and Tokens in Ledger | Users sheet has only `xp_balance`; no representation of premium Gems or platform Tokens exists | Multi-currency economy cannot be analyzed; tokenomics and monetization metrics cannot be calculated | High | Define explicit currency schemas for XP (experience), Gems (premium hard currency), and Tokens (redeemable cash/crypto value) | Proposed |
| GAP-009 | Help Center | Missing Customer Support Interaction Telemetry | Help Center is only listed as a session entry point; zero FAQ view, article search, or support ticket events exist | Blind spot regarding user frustration, onboarding confusion, withdrawal inquiry volume, and bug reports | Medium | Instrument `faq_viewed`, `search_executed`, `support_ticket_created`, `support_ticket_resolved` events | Proposed |
| GAP-010 | Ad Network | Missing Ad Network SDK Attribution & eCPM Metadata | Ad events capture start, skip, and complete, but do not record ad network partner (AdMob, Unity, AppLovin), ad unit type, or revenue eCPM | Cannot measure monetization yield per ad network, fill rates, or partner performance discrepancies | High | Enrich ad events with: `network_partner`, `ad_placement_id`, `ad_format` (interstitial vs rewarded), `estimated_cpm` | Proposed |
| GAP-011 | Missions | Lack of Mission Progression & Step-Level Telemetry | Events capture start, completed, and abandoned, but no incremental milestone progression (e.g. 3 of 5 steps finished) | Cannot identify bottleneck steps within complex multi-step reward missions | Medium | Instrument `mission_step_completed` with `step_number`, `total_steps`, `percent_complete` | Proposed |
| GAP-012 | Data Quality | Dirty Data Injection in Event Streams (Messy Audit Sheet) | `10_Event_Data_Quality_Audit` contains duplicate event IDs, lowercase feature names, null sequence numbers, and unverified devices | Analytics queries will produce skewed aggregates, broken dashboard filters, and duplicate counts if run directly on raw data | High | Deploy pipeline automated data quality validation layer with schema enforcement, casing standardization, and deduplication | Proposed |
| GAP-013 | Sessionization | Incomplete Session State Modeling on Mobile Interruptions | Sessions are modeled with start and end, but no background/foreground transition events or app crash telemetry | Abrupt mobile app terminations are counted as abandoned sessions rather than technical failures | Medium | Implement `app_backgrounded`, `app_foregrounded`, and crash diagnostic SDK integration | Proposed |
| GAP-014 | Privacy & PII | Plaintext PII Storage in Analytical Data Layers | `Users` sheet includes plaintext `full_name` and `email` directly in the analytical reporting view | Violates privacy best practices (GDPR/DPDP); exposes sensitive personal data to unauthorized analytical consumers | High | Implement pseudo-anonymization: hash or mask email and name in analytical marts; restrict raw PII to production auth database | Proposed |
| GAP-015 | Schema Documentation | Absence of Centralized Enterprise Data Dictionary | Supplied data dictionary sheets contain only 25-26 fields; lacks unified catalog covering all 18 domains and 75+ core entities | Cross-functional confusion between engineering, analytics, and product teams on metric definitions and field validations | High | Publish complete 75+ field enterprise Data Dictionary (Deliverable 09) with validation rules, sensitivity tiers, and owners | Proposed |

## Current implementation status 

This deliverable is an analytical specification/report and must be read separately from runtime verification. The current Streamlit source contains seven navigation sections: Overview, User Analytics, Earning & Rewards, Wallet & Withdrawal, Referral & Virality, Feature & Engagement, and Data Quality & Audit. Workbook-level simulated records are not interchangeable with PostgreSQL-loaded records.

The supplied PostgreSQL execution evidence is marked `AUTH_REQUIRED_NOT_VERIFIED`; successful live database execution is therefore not established by that evidence. The automated project test suite was rerun for this archive and passed 40/40 tests. This does not verify live PostgreSQL, production payment settlement, or public dashboard deployment.

Wallet, withdrawal, user, session, event, task, and milestone examples are simulated/test data. Referral event activity must not be described as verified referral conversion without validated referrer/referee relationship records. A proposed schema or KPI definition is not evidence that the corresponding production workflow is deployed.
